# Open-source macOS app research

Reviewed on 21 September 2026: 11 projects and 34 source, README, or changelog files. This is a source review, not a benchmark of other apps. The links below pin the reviewed code to specific commits. No third-party code was installed, executed, or copied into Dynamite. The settings redesign is implemented; the proposals below are not.

## What the HUD research actually establishes

Several current projects intercept keyboard events before macOS handles them. Dynamite already does this. It explains why those apps can advertise native HUD replacement without proving they can suppress the first frame of a Bluetooth stem-volume popup.

The inspected SlimHUD code suspends the older OSDUIHelper process. This Mac's captured volume, Focus, and AirPods connection windows belong to MenuBarAgent. Applying the legacy suspension method would not be an evidence-based fix for the remaining first-swipe flash. None of the inspected source paths establishes a pre-presentation solution for this specific macOS 27 case.

AirDrop claims also need care: the reviewed MewNotch and NotchDrop implementations initiate outgoing sharing. That is useful functionality, but not an incoming receive-progress API.

## Improvements worth pursuing

1. **Monitor-specific calibration and recovery.** Keep brightness mapping and DDC retry timing per display, and test disconnect/reconnect during a smooth ramp. MonitorControl is the reference. This improves an existing integration rather than adding another persistent widget.
2. **Battery freshness and broader accessory support.** Add real Magic Keyboard, Mouse, and Trackpad battery providers, and distinguish a fresh reading from a last-known one. Keep refreshes event-driven or explicitly requested. AirBattery demonstrates the data sources, but its broader periodic scanning is not the default we should copy.
3. **Explicit ownership of open interactions.** Model a share sheet, file drag, or expanded action as a session with a single completion/cancel path. boringNotch's sharing-lifetime handling is useful here. It could reduce the dismissal edge cases that have required repeated animation fixes.
4. **One reminder planner, independently tested.** Use stable activity/event identity and explicit cancellation/expiry rules for future reminders. MeetingBar's planner is a good reference for avoiding duplicate meeting alerts and late reminders after events change. Dynamite already has scheduling state machines; this would extend that approach.
5. **Device capability reporting.** Separate "can observe this device" from "can control it," retain native fallback when writes fail, and expose a concise unavailable reason only when needed. volumeHUD and MonitorControl are useful comparisons. Much of this exists already; the remaining value is coverage of unusual output devices.

## Integration shortlist

These are proposals, not promises that all private APIs will behave on every macOS release. Cost estimates are engineering judgments based on the inspected mechanisms, not measured CPU figures.

| Priority | Idea | A quiet Dynamite version | Starting point / cost |
|---|---|---|---|
| 1 | Audio output or microphone source changed | Brief device icon and name when the actual system route changes. Especially useful when AirPods steal a call or a dock connects. | Existing CoreAudio route listeners plus the volumeHUD and boringNotch audio patterns. Low expected idle cost. |
| 2 | Accessory low battery | One warning per threshold crossing for AirPods, Magic Keyboard, Mouse, or Trackpad; optional charging-complete confirmation. | AirBattery provider research. Medium effort; availability varies by device. Avoid continuous scans. |
| 3 | Microphone/camera activity | Optional start/stop confirmation, distinct from mute state; expand only on request. Apple's privacy indicators remain intact. | OverSight. Basic device state is simpler than reliable per-app attribution. Medium to high effort. |
| 4 | Next meeting + Join | Show only shortly before a chosen calendar meeting, with time remaining and a Join action; ignore declined/all-day events. | MeetingBar's EventKit adapter and reminder planner. Medium effort, optional Calendar permission. |
| 5 | Keep Awake session | Small coffee icon and remaining time for a session started from Dynamite, with a Stop action. | KeepingYouAwake. Low implementation effort; the session intentionally prevents sleep. |
| 6 | Now Playing on demand | Brief track-change confirmation; hover for play/pause and source-app open. No always-running decorative visualizer. | boringNotch music controller. Medium to high effort because media sources and private APIs vary. |
| 7 | Temporary file shelf + Send via AirDrop | Appears during a file drag, holds a small bounded set, and opens native sharing from the island. | NotchDrop and MewNotch. Medium effort; outgoing sharing, not incoming progress. |

My first choices for this app are route changes, accessory low-battery alerts, and a short next-meeting reminder. They answer a specific question quickly and do not require another permanent dashboard.
